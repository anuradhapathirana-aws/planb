# Changelog — Plan B International

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## Unreleased

### Added
- Project scaffolding: Laravel 11 backend (`backend/`, PHP 8.2, MySQL 8), React 18 + TypeScript + Vite 8 + Tailwind v4 web app (`web/`). Backend dev server pinned to port **8001**, web dev server pinned to port **5183** with `strictPort: true` — 8000 and 5173 were already occupied by an unrelated local project on this machine.
- `docs/schema.md` — schema for `users` (admin/staff auth) and `students` (Student Management), plus notes on what's deferred to later modules.
- Admin auth (FR-ADM-001–004): Sanctum SPA cookie login, Spatie Permission roles (Super Admin, Content Manager, Support Agent, Accountant), 5-failed-attempt lockout with email-based unlock link (NFR-008), 8-hour session lifetime (NFR-009).
- Student Management (FR-ADM-005, FR-ADM-006, FR-ADM-007): list with search/status filter/sort/pagination, create, edit, block/unblock, soft delete, bulk CSV Student-ID import with per-row results, live stats, student detail page with a real Profile tab plus placeholder Progress/Payments/Orders tabs (those modules aren't built yet).
- Admin panel shell: branded sidebar (desktop) / drawer (mobile) navigation showing the full intended nav with "Soon" badges on unbuilt sections (Courses, Checklists, Jobs, Success Stories, Orders, Payments, Notifications, Accounts, Reports, Settings), dashboard with real student stats.
- Backend feature test suite (19 tests, `tests/Feature/Admin/`) covering admin auth and Student Management happy paths + key error paths; SQLite in-memory for test isolation from the dev MySQL database.
- Hand-authored shadcn/ui-style component primitives (`web/src/components/ui/`) on Radix UI + Tailwind v4, since both the current and previous major versions of the `shadcn` CLI errored out in this environment (registry/schema validation failures — see notes below).
- Reworked Students list page to a denser, client-referenced admin style: removed the stat-card row from the page header (stats stay on the Dashboard only), moved search/status/visa-status filters into a new reusable `components/shared/FilterCard.tsx` (collapsed by default, staged edits, explicit "Apply Filter"/"Clear"), and tightened spacing/button sizes across the Students feature (new `sm`/`xs`/`icon-sm` Button sizes, compact `Table` cell padding with uppercase headers, `p-5` dialog padding). Documented as the standard pattern for all future admin list pages in CLAUDE.md §8 "Compact Admin Data Tables".
- Auto-generated Student IDs: "Add student" no longer asks the admin for a Student ID — `StudentManagementService::nextStudentId()` picks the next sequential `PB-#####` under a row lock so concurrent submissions can't collide. CSV bulk import is unaffected (it still consumes the `student_id` supplied per row). The Student ID field is now read-only on the Edit form and absent from the Add form.
- Student profile photo upload: `POST /admin/students/{student}/photo` (replace) and `DELETE /admin/students/{student}/photo` (remove), backed by the `profile_photo` Spatie Media Library collection already defined on `Student`. Uploads are validated (jpeg/png, max 2MB) and re-encoded server-side with `intervention/image` (600×600 cover crop, stripping EXIF/metadata) per CLAUDE.md §7.4 before being stored — never saved as-received. Student Detail page now has a camera-badge control on the avatar to upload/replace, and a remove button once a photo exists.
- The Add/Edit student dialog now also has the photo control and a disabled Student ID field (`web/src/features/admin/students/components/StudentFormDialog.tsx`). Editing an existing student uploads/removes the photo immediately (a real ID already exists). Adding a new student stages the picked file client-side (local preview, no request yet) since there's no ID to attach it to until the record is saved — clicking "Add student" creates the record, then uploads the staged photo as an automatic follow-up request, then closes the dialog.
- The Add-student Student ID field now shows the actual next ID (`GET /admin/students/next-id`, `StudentManagementService::previewNextStudentId()`) instead of a placeholder, so the admin sees the real value before saving. It's a preview only, not a reservation — the same locked computation runs again on create, so a concurrent create or CSV import can still take the previewed number first; the form just shows whichever ID actually ends up unused at save time.
- Removed the drop shadow from the shared `Card` primitive (`web/src/components/ui/card.tsx`) — border-only now. Stacking several cards on the dashboard/list/detail pages was reading as visually heavy with `shadow-sm` on every one; dialogs/sheets keep `shadow-lg` since they float above the page. Documented in CLAUDE.md §8.
- Redesigned the Add/Edit student dialog (`web/src/features/admin/students/components/StudentFormDialog.tsx`) into an LMS-style sectioned layout: a bordered identity panel (photo + auto-generated Student ID) followed by bordered "Basic information" / "Contact details" / "Academic & career" sections, wider dialog (`sm:max-w-2xl`), icon-prefixed field labels matching the Student Detail page's `InfoRow` icon vocabulary.
- Industries & Professions master data (FR-ADM-012, extended beyond the SRS's flat-list wording at the client's request to add an Industry grouping): new `industries` and `professions` tables, full CRUD (Super Admin + Content Manager; any admin role can read), `is_active` deactivate-instead-of-delete pattern (no hard delete — see `docs/schema.md`). New admin pages `web/src/features/admin/industries/pages/IndustriesListPage.tsx` and `web/src/features/admin/professions/pages/ProfessionsListPage.tsx`, both following the standard Compact Admin Data Table pattern. Reachable from a new expandable "Jobs" sidebar group (`web/src/components/layout/AdminSidebar.tsx` now supports nested sub-items via `AdminNavItem.children`) with "Job Posts" (still coming soon), "Industries", "Professions".
- The Student form's free-text "Profession category" field is replaced by a cascading **Industry → Profession** pair of selects (`students.profession_category` dropped; `students.industry_id`/`students.profession_id` added). Choosing an Industry loads only that industry's active Professions and clears any previously chosen Profession that no longer applies; the Profession select is disabled until an Industry is picked. `StoreStudentRequest`/`UpdateStudentRequest` validate that `profession_id` actually belongs to the given `industry_id`. Backend feature test suite grew to 42 tests (`IndustryManagementTest`, `ProfessionManagementTest`, plus new Student Management cases).
- Restyled the Add/Edit student dialog's Photo and Visa status fields to match a client-supplied reference (a card-sectioned form with a dropzone photo upload and pill-style choice buttons), reskinned to Plan B's navy/gold palette instead of the reference's colors. The compact photo+ID identity strip is now its own "Photo" `FormSection` with a full-width dashed dropzone (click **or** drag-and-drop, `UploadCloud` icon, PNG/JPG + size hint) that fills with the actual photo (change/remove buttons overlaid) once one exists; Student ID moved into "Basic information" as a small read-only field. Visa status changed from a `Select` to a two-button `PillToggle` (Visit/Employment, each with an icon) since it only ever has two options. Documented as the standard pattern for future multi-section admin forms in CLAUDE.md §8 "Sectioned Admin Forms".
- **Full name, date of birth, visa status, contact number, address, industry and profession are now required** on the admin Add/Edit student form (client-requested change from the SRS's original "all optional until self-registration" design) — email and highest qualification stay optional. Scoped to the single-record admin form only; CSV bulk import (FR-ADM-006) is unchanged and still only needs `student_id`. Editing an existing "pending registration" student (bulk-imported with just a Student ID) now requires backfilling all required fields before the edit can be saved. `StoreStudentRequest`/`UpdateStudentRequest` (`backend/app/Http/Requests/Student/`) carry the backend validation; `studentSchema.ts` mirrors it with Zod. The form (`StudentFormDialog.tsx`) validates in real time — `mode: 'onBlur'` checks a field once the admin tabs away, `reValidateMode: 'onChange'` (RHF's default) then live-clears the error as they fix it — with a red asterisk on every required label and `aria-invalid` styling now added to the shared `Select` primitive (`components/ui/select.tsx`) to match `Input`/`Textarea`. New tests: `test_creating_a_student_without_required_fields_fails_validation`, `test_admin_must_backfill_required_fields_to_update_a_pending_registration_student`.
- Adopted `UI_UX_GUIDELINES.md` (new root-level doc) as the project's UI/UX standard, referenced from CLAUDE.md §8. This pass applies its structural/performance requirements across the admin panel (colors/spacing continue to follow CLAUDE.md's own Plan B design-system section, not the guideline doc's generic slate-palette wording):
  - **Extracted the Sectioned Admin Forms building blocks into `web/src/components/shared/`** — `FormSection.tsx`, `FormField.tsx` (`FieldLabel`/`FieldError`), `PillToggle.tsx` — out of `StudentFormDialog.tsx`, where they'd been defined locally. They were already documented in CLAUDE.md §8 as a reusable pattern for future forms (Courses, Jobs, Orders); now they actually are reusable rather than needing to be copy-pasted per form.
  - **Route-based code splitting**: every page component and `AdminLayout` itself is now `React.lazy`-loaded in `src/routes/router.tsx`, wrapped in `<Suspense>` (new shared `PageLoader`/`FullScreenSpinner` components). Verified via `npm run build` that each page ships as its own chunk. Set up now, while there are only 5 real routes, rather than retrofitting once Courses/Jobs/Payments/the student area exist and genuinely need the isolation (video.js, Recharts, etc. shouldn't ship to users who never visit those areas).
  - **Sticky table header + sticky right-hand action column**, built into the shared `Table`/`DataTable` primitives so Students/Industries/Professions (and every future list page) get it automatically. Required switching the table container from `overflow-x-auto` to an explicit `max-h-[65vh] overflow-auto` — an x-only overflow container silently breaks `position: sticky` for the header. A column opts into sticking via `meta: { sticky: 'right' }` on its `ColumnDef` (added to each `*Columns.tsx` actions column).
  - **New `Breadcrumbs` component** (`components/shared/Breadcrumbs.tsx`), added to the Student Detail page (`Students > [name]`), replacing the old "Back to students" button. Reserved for nested/drilled-into pages — top-level sidebar pages don't get one.
  - **Desktop content-width cap**: `AdminLayout`'s `<main>` is now `mx-auto max-w-7xl`, so content stops stretching edge-to-edge on very wide (1920px+) monitors while standard 1366–1920px business monitors are unaffected.

- Add/Edit student form refinements (client-requested UI pass) plus two real validation fixes:
  - **Minimum age 18.** `date_of_birth` must now be on or before today minus 18 years, enforced in `StoreStudentRequest`/`UpdateStudentRequest` (`before_or_equal:` against a `MIN_AGE_YEARS` const, with a plain-English `messages()` override) and mirrored in `studentSchema.ts`, which separates "not a real date" / "in the future" / "under 18" into distinct messages. The date input also sets `max` to the cutoff so the native picker can't offer an invalid date. Turning 18 today is allowed. New tests: `test_creating_a_student_under_18_fails_validation`, `test_creating_a_student_who_turns_18_today_is_allowed`, `test_creating_a_student_with_a_future_date_of_birth_fails_validation`.
  - **Backend validation errors now land on the field that caused them.** Saving a duplicate email returned a 422 with `errors.email`, but the mutation hook discarded it and showed a generic "Could not add student." toast that never said which field was wrong. New `web/src/lib/serverErrors.ts` (`getValidationErrors`, `applyServerValidationErrors`) maps a Laravel 422 onto RHF field errors, guarded by the form's known field names so an unrenderable error can't silently block resubmit. `useStudents.ts` now only toasts non-422 failures, so there's no duplicate messaging.
  - Validation timing changed to blur-only (`reValidateMode: 'onBlur'`, was `'onChange'`) — no error appears or updates mid-keystroke. CLAUDE.md §8 updated.
  - Layout: Full name + Visa status share a row; "Academic & career" is a single 3-across row (`FormSection` gained a `columns?: 2 | 3` prop); Photo is now a circular avatar preview on the left with the dashed dropzone beside it, instead of one wide box that letterboxed the image; header/footer dividers removed; spacing tightened throughout (`FormSection` `p-3`/`gap-x-3 gap-y-2.5`, dialog `p-4`, fields `space-y-1`).
  - Form controls restyled globally in `components/ui/`: transparent backgrounds (was `bg-background` plus per-field `bg-muted/40` overrides), no focus ring box-shadow — focus is a subtle border shift to `border-ring/45` — `shadow-xs` instead of `shadow-sm`, and heights down from `h-10` to `h-8` (`SelectTrigger` sm to `h-7`) to match `size="sm"` buttons.
  - `PillToggle` replaced by `SegmentedToggle` (`components/shared/`) — a single `rounded-full bg-primary` track with the selected option lifted out as a light pill, per a client-supplied reference. Visa status defaults to Visit. `FormSection`'s icon badge is now solid primary with a white glyph. CLAUDE.md §8 updated for both.

- **Data-table row actions changed from a dropdown menu to individual icon buttons** (client-requested). New shared `web/src/components/shared/RowActions.tsx` takes a `RowAction[]` (`label`, `icon`, `onClick`, optional `variant: 'destructive'`, `disabled`, `hidden`) and renders one `icon-sm` ghost icon button per action instead of a `MoreHorizontal` menu, so Edit / Block / Delete are one click away rather than two. Applied to all three existing list pages (`studentColumns.tsx`, `industryColumns.tsx`, `professionColumns.tsx`) and documented in CLAUDE.md §8 as the standard for every future list page.
  - Icon-only buttons need labels, so this adds the `Tooltip` primitive (`web/src/components/ui/tooltip.tsx`) on `@radix-ui/react-tooltip` — already a dependency, no new package — with a single `TooltipProvider` mounted around the router in `main.tsx`. Each button also carries an `aria-label`.
  - Icons render in every row at all times rather than on hover only: hover-reveal is invisible on touch devices, and the admin drawer layout is used on tablets.
  - Actions past the first 3 collapse into a trailing overflow menu (`maxInline`, default 3) so the sticky right-hand action column can't bloat as future tables (Orders, Payments, Courses) accumulate actions.
  - `RowActions` stops click propagation internally, so the per-column `<div onClick={(e) => e.stopPropagation()}>` wrapper each `*Columns.tsx` had been repeating is gone.

### Notes / follow-ups
- PWA icons (`web/public/icons/`) are placeholders — the full-resolution brand logo copied to all three required sizes. Generate properly optimized 192/512/maskable PNGs before shipping.
- `RequireRole` (per CLAUDE.md §4 Web rule 12) isn't built yet — only `RequireAuth` exists, since there's no student-facing area yet to separate from admin. Add it when the student mobile-web area or role-gated admin sections arrive.
- Zod pinned to `3.23.8` (not latest 3.25.x) and TypeScript to `^5.9` (not the auto-installed 6.0 prerelease) — both for ecosystem compatibility with `@hookform/resolvers` v3 and general tooling stability.
- Queues use the `database` driver locally (not Redis) — Redis isn't running in this dev environment. CSV import runs synchronously (bounded, with per-row validation feedback needed immediately); switch to Redis + queued jobs per CLAUDE.md before production.
- Fixed during browser verification: several hand-authored `ui/` primitives (`Input`, `Textarea`, `Button`, `Dialog`/`Sheet`/`AlertDialog` Overlay+Content, `DropdownMenuContent`, `SelectContent`) weren't forwarding refs, which silently broke every React Hook Form field (login, student form) and any `asChild`-based trigger. All now use `React.forwardRef` — required because the project is pinned to React 18, which (unlike React 19) doesn't accept `ref` as a plain prop on function components.
