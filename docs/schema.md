# Database Schema — Plan B International

> Source of truth for all tables. Update this file in the same commit as any migration.
> Every new table must be proposed here and approved before the migration is written (see `CLAUDE.md` §12.4).

## Conventions

- Tables: `snake_case`, plural.
- Primary keys: `id` (bigIncrements).
- Foreign keys: `{singular_table}_id`.
- Timestamps: `created_at`, `updated_at`, (`deleted_at` where soft-deletable).
- Booleans: `is_*` / `has_*`.
- Money: `*_cents` (integer, never float).

---

## `users`

Staff / admin panel accounts only. **Not** students — students never log into this table.

| Column | Type | Notes |
|---|---|---|
| id | bigIncrements | |
| name | string | |
| email | string, unique | |
| password | string | hashed (bcrypt) |
| failed_login_attempts | unsignedTinyInteger, default 0 | NFR-008 |
| locked_until | timestamp, nullable | NFR-008: lock 5 fails, email unlock |
| email_verified_at | timestamp, nullable | |
| remember_token | string, nullable | |
| created_at / updated_at | timestamps | |

Roles (Super Admin, Content Manager, Support Agent, Accountant) via **Spatie Permission** package tables (`roles`, `permissions`, `model_has_roles`, `model_has_permissions`, `role_has_permissions`) — package-managed, not hand-designed here.

Auth tokens: Sanctum `personal_access_tokens` (package-managed). SPA auth is cookie/session based (`sessions` table), per CLAUDE.md §4.

## `students`

Records pre-loaded by admin (FR-ADM-006 bulk CSV import of Student IDs) and later filled in by the student via self-registration on the mobile app (FR-MOB-003/004). The admin panel is the only way to create/edit/block/delete these records in Phase 1 (mobile self-registration endpoints are a future feature, out of scope for this Student Management pass).

Columns below marked "nullable" stay nullable at the DB level (CSV-imported rows and not-yet-self-registered students legitimately have them blank) — but `full_name`, `contact_number`, `address`, `date_of_birth`, `visa_status`, `industry_id` and `profession_id` are **required by `StoreStudentRequest`/`UpdateStudentRequest`** on the single-record admin Add/Edit form (client-requested; CSV import is unaffected). Editing an existing blank/pending record requires backfilling all of them.

| Column | Type | Notes |
|---|---|---|
| id | bigIncrements | |
| student_id | string, unique | Plan B-issued ID. Auto-generated by the backend on single-record create (`PB-#####`, sequential, next-after-max locked per transaction); CSV bulk import instead supplies its own `student_id` per row |
| full_name | string, nullable | null until self-registration or CSV import; **required** on the admin form |
| email | string, nullable, unique (when present) | optional everywhere |
| contact_number | string, nullable | **required** on the admin form |
| address | string, nullable | **required** on the admin form |
| date_of_birth | date, nullable | **required** on the admin form |
| highest_qualification | string, nullable | optional everywhere |
| industry_id | unsignedBigInteger, nullable, FK → `industries.id`, ON DELETE SET NULL | FR-ADM-012. One industry per student. **Required** on the admin form. |
| profession_id | unsignedBigInteger, nullable, FK → `professions.id`, ON DELETE SET NULL | FR-ADM-012. One profession per student; many students can share a profession. Must belong to `industry_id` when both are set (validated in `StoreStudentRequest`/`UpdateStudentRequest`, not a DB constraint). **Required** on the admin form. |
| visa_status | enum: `visit`, `employment`, nullable | PHP enum `App\Enums\VisaStatus`. **Required** on the admin form. |
| languages_spoken | json, nullable | array of strings |
| is_blocked | boolean, default false | FR-ADM-005 |
| registered_at | timestamp, nullable | null = imported but not yet self-registered on mobile |
| imported_by | unsignedBigInteger, nullable, FK → `users.id` | audit: who bulk-imported this row |
| created_at / updated_at / deleted_at | timestamps + soft delete | delete is soft (FR-ADM-005 "delete" = recoverable) |

Profile photo: **Spatie Media Library** (`media` table, package-managed), collection `profile_photo`, single-file, per CLAUDE.md §4.

## `industries`

FR-ADM-012: admin-managed grouping for the profession list. Super Admin and Content Manager create/edit; any admin role may read (e.g. to populate the Student form's Industry select).

| Column | Type | Notes |
|---|---|---|
| id | bigIncrements | |
| name | string, unique | e.g. "Hospitality", "Construction" |
| is_active | boolean, default true | Inactive industries (and their professions) drop out of the Student form's selects but stay intact for students who already reference them. No hard delete — deactivate instead. |
| created_at / updated_at | timestamps | |

## `professions`

FR-ADM-012. Every profession belongs to exactly one industry; the Student form's Profession select is filtered by the chosen Industry (cascading select).

| Column | Type | Notes |
|---|---|---|
| id | bigIncrements | |
| industry_id | unsignedBigInteger, FK → `industries.id`, cascade delete | Required — a profession cannot exist without an industry. |
| name | string | Unique per industry (`unique(industry_id, name)`), not globally — the same title can exist under different industries. |
| is_active | boolean, default true | Same deactivate-not-delete pattern as `industries`. |
| created_at / updated_at | timestamps | |

### Deferred (not built yet, referenced by future features)

These are named in the SRS but belong to other, not-yet-built modules. `students` does not reference them yet; the Student Detail page shows placeholder tabs instead:

- Course progress (`Phase`, `Topic`, `Video`, `Assessment`, `Progress`) — Course Module feature.
- Payments (`Order`, `Payment`, `BankTransfer`) — Payment Gateway feature.
- Premium service orders (`PremiumService`, `ServiceOrder`) — Premium Services feature.
